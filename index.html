Guia Kubernetes

A Ana tem a padaria, o site do cardápio e agora um problema novo: o site não pode cair. Antes, ela abria um terminal e deixava o programa rodando; se a máquina reiniciasse, o site saía do ar até alguém perceber. Este guia ensina Kubernetes do começo — o que é um cluster, o que é um pod, como se escreve um manifesto, como o site fica no ar sozinho, como escalar, como descobrir o que quebrou — até o dia em que ela descreve o que quer e o cluster mantém de pé. Escrito em português, para quem nunca programou.

Como este guia funciona
  • 144 aulas, uma ideia por aula, na ordem em que se aprende de verdade.
  • Toda caixa \"Experimente\" aplica o seu manifesto num cluster e mostra a resposta como o kubectl mostraria: a linha do apply, a tabela do get, o erro do API server, o evento do agendador.
  • As mensagens de erro do motor foram conferidas com um cluster de verdade (kube-apiserver, scheduler e controller-manager reais) — uma a uma, em tools/conferir.js.
  • Não precisa instalar nada para começar: o painel já traz o leitor de YAML e o cluster simulado.

1. Para quem é

Para quem nunca escreveu uma linha de código e ouviu falar que “hoje tudo roda em Kubernetes”. O guia não supõe que você saiba Linux, Docker ou YAML: cada peça aparece quando é necessária, explicada na hora. Se você já usa Docker no dia a dia, o começo vai parecer devagar — é de propósito, porque a Ana ainda confunde “container” com “imagem”.

Se você já mexeu com Kubernetes antes, comece pela Referência: são doze páginas de consulta, com tabelas de kubectl, campos de manifesto, mensagens de erro e glossário, cada uma com o que fazer.

2. O primeiro pod, agora

Este é o mesmo manifesto que a oitava aula aplica. Leia, clique em Rodar e veja o que o cluster responde. O painel não é uma imagem: é o resultado de aplicar esse YAML — validação, agendamento e a tabela do get.

Missão: o manifesto abaixo cria um pod com a imagem errada. Troque a imagem para cardapio:1.0 (a do site da padaria) e rode.

apiVersion: v1
kind: Pod
metadata:
  name: cardapio
spec:
  containers:
    - name: web
      image: nginx:1.29
      ports:
        - containerPort: 8080
pod/cardapio created

NAME       READY   STATUS    RESTARTS   AGE
cardapio   1/1     Running   0          2m

apiVersion: v1
kind: Pod
metadata:
  name: cardapio
spec:
  containers:
    - name: web
      image: cardapio:1.0
      ports:
        - containerPort: 8080

O painel mostra duas coisas: a linha do apply e a tabela do get pods. Se o manifesto tivesse um erro — nome com maiúscula, campo obrigatório faltando, seletor que não casa — o painel mostraria a mesma frase que o API server do Kubernetes devolve. É assim que o guia confere tudo: pelo resultado, não pela aparência do código.

3. O que você vai construir

No fim do Nível 1, a Ana tem o site da padaria rodando dentro do cluster: um pod, depois um ConfigMap com o cardápio, um Secret com a senha do banco, e a rotina de olhar o get, o describe e os logs quando algo sai errado. No Nível 2, o site vira aplicação de verdade: Deployment com réplicas e rollout sem queda, Service para os outros pods acharem o site, Ingress para o mundo chegar nele, probes para o cluster saber quem está pronto, volume para o banco guardar dados e HPA para crescer quando a fila aumenta.

No Nível 3, o assunto deixa de ser “fazer funcionar” e vira “fazer durar”: RBAC para cada pessoa ver só o que deve, métricas e logs para enxergar o cluster, Helm e Kustomize para não repetir YAML, GitOps para o cluster seguir o repositório, backup, upgrade e o que fazer quando o incidente é às três da manhã.

4. Como estudar

Uma aula por vez, na ordem, com o terminal e o painel abertos. Ler sobre pod não ensina pod: editar o manifesto, rodar e ver a resposta mudar, sim. Depois de cada aula, refaça o exercício no seu próprio arquivo e aplique no cluster local (kind) — o guia ensina a montar um no Nível 1, aula 6. Quando o painel e o seu cluster discordarem, confie no seu cluster e leia o evento com kubectl describe.

A resposta está nos eventos

Quem está começando tenta adivinhar por que o pod não sobe. O caminho certo é o contrário: rodar kubectl describe pod nome e ler os events do fim. Nove entre dez vezes o cluster já escreveu o motivo — falta de CPU, imagem que não existe, etiqueta que não casa.

5. O que este guia não é

Não é a documentação oficial: para a lista completa de campos existe a referência do Kubernetes, e as páginas de consulta apontam o caminho. Não é um curso de Docker: o que aparece de imagem e container é explicado na hora. E não é um curso de nuvem: quando o assunto é provedor, o guia mostra o conceito e diz o que muda em cada um, sem vender nenhum.

6. Resumo

Kubernetes é um cluster que mantém de pé o que você descreve: você escreve o manifesto, ele agenda, liga, vigia e recoloca no ar. Este guia começa no pod — a menor peça — e vai até o cluster de produção, com 144 aulas, caixas que respondem como o kubectl e a honestidade de dizer quando um estado é transcrição de um cluster real e não cálculo do painel.

Se você só puder ler uma página antes de começar, leia O Primeiro Pod: ela mostra o ciclo inteiro — comando, manifesto, tabela, describe, erro — e é o padrão que todas as outras seguem. Depois siga a ordem do menu: cada aula supõe a anterior e nada além dela.
